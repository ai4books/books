# /qa-sweep — One QA-Hardening Iteration

You are ONE iteration of the "EPIC: Continuous QA Hardening & Bug Sweep" in
[BACKLOG.md](BACKLOG.md). Do one small, well-scoped chunk of work, then stop.
Another iteration runs on the next loop tick.

If the repo has no BACKLOG.md or no Continuous QA epic, say so and stop — this
skill does not fabricate a backlog.

## Steps

1. **Pick the work.** Read the epic in BACKLOG.md. Take the TOP unchecked story
   (QA-1 first, then QA-2, ...), or the story id passed as an argument. Within it,
   pick the next unfinished chunk: ONE feature, ONE route group, or ONE `lib/` /
   `app/api` module. Keep it small enough to finish and verify in a single run.

2. **Verify before you touch.** Read the code for that chunk. Establish how it is
   supposed to work. Where practical, exercise it: a unit test, a gated test
   route, or a read-only live check against this project's own deployed URL
   (public pages only) where one exists. Do NOT assume a bug, reproduce it.

3. **Fix only real bugs.** If you reproduce a genuine defect, fix it in this run
   and note the failure mode. If the chunk is already correct, say so and add a
   regression test that would catch a future break, then move on. Do NOT invent
   work or add filler tests to look busy.

4. **Add real regression tests** for the chunk (meaningful assertions on
   behavior, edge cases, and failure paths). Keep AI/provider tests on the mock
   providers; never trigger real provider spend beyond a single cheap read-only
   probe.

5. **Gate with the repo's own checks (all must pass, in order); never push red.**
   For a Node/TS repo: `npx tsc --noEmit` (FULL) → `npx eslint <changed files>` →
   `npx vitest run <touched test files>`. For another stack, run the repo's
   equivalent typecheck / lint / test. The pre-push hook re-runs the full suite
   as the real gate.

6. **Commit + push to `main`.** Conventional message (feat/fix/test/docs). Push
   directly to `main` (autonomous-experiment mode). The push runs the pre-push
   gate (can take 3-4 min); that is expected. Respect branch protection: if the
   push is rejected, open a PR instead of bypassing.

7. **Record progress** in BACKLOG.md in the same commit: append a dated line
   under the epic's "Progress log" with what you verified/fixed. Check a story's
   box off only when every chunk under it is done.

8. **Report** concisely: which story/chunk, what you found (bug or clean), what
   you changed, and gate results.

## Hard rules

- ONE small chunk per run. Finish and push, or explicitly stop with a clean tree.
- Never destructive. Never touch live Stripe product/price/webhook wiring, never
  copy live keys into files, never mutate live provider resources. Respect the
  two-confirmation rule for any destructive action (do not do it in the loop).
- DB migrations for genuine drift only, via the project's migration path,
  documented in BACKLOG.md. No schema changes that aren't needed by the chunk.
- If a chunk is blocked (needs owner creds/decision), note it under the epic and
  move to the next chunk instead of stalling.
- If the whole epic is complete or nothing actionable remains, say
  "QA epic idle: nothing actionable" and stop (do not fabricate work).
