# secret-scan-allowlist.txt: the paths where secret-shaped strings are supposed
# to live. Anything else that trips the scanner is a real finding.
#
# A secret scanner has one unavoidable irony: the detector, its tests, and its
# documentation must all contain the very patterns it hunts for. Without a
# managed allowlist, the library flags itself, everyone learns the gate cries
# wolf, and the next real leak scrolls past in a wall of known noise. An
# allowlist is not a way to silence the gate. It is what keeps the gate
# credible enough that a red result still means something.
#
# Extended regexes (grep -E), matched against repo-relative paths. Keep every
# entry as narrow as it can be, and add a comment saying why it is here.
# Blank lines and #-comments are ignored.

# The planted fakes the eval suite asserts against. These are deliberately
# structurally broken so no real scanner treats them as live keys.
^skills/audit-secrets/tests/fixtures/

# The pattern catalogue the Skill cites: packaged context, not tribal knowledge.
^skills/audit-secrets/reference/

# The detector itself. It cannot hunt for a prefix without naming it.
^skills/audit-secrets/scripts/scan\.mjs$

# The eval harness asserts on marker strings to prove the detector fires.
^eval/run\.mjs$

# The sibling detector's own pattern list.
^checks/public-prefix-leak-scan\.sh$
